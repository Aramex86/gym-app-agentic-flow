trust core

What’s in the core: four iron laws

The philosophy: an agent may say anything — a verdict is accepted only when a fact, not a claim, confirms it.

core · law 1

Machine-verified verdict

The tester claims PASS — the engine re-runs the project passport itself (lint, typecheck, tests, build) and shows you ✓/✗ with timings, live. A disagreeing machine demotes the verdict and stops the circle honestly with a trace receipt. Proven in combat.

core · law 2

Cost, to the penny

The budget cap is your choice (PIPELINE_BUDGET_USD in .env). Unset = honest unlimited. Set = hard stop with the budget sheet before the most expensive hop — including --fix.

core · law 3

Secrets travel only via env

Keys are never printed, logged or embedded in prompts. No key = “missing secret” stop before the hop spawns — never a mid-circle 401 mystery. Copilot rail: auth lives in your company CLI login; the factory never asks for a key.

core · law 4

A fully honest journal

Every circle writes events: Y/N gate decisions (one each, deduplicated), spend, tokens, the verdict (machine-confirmed, exactly once), circle_end. A failed circle leaves the same full receipt as a passing one.

laws, filed as documents

Every decision is an ADR with a date and an author

The factory obeys the same protocol it demands from projects: decisions in ADR-0001…0008, the domain language in the glossary, a drift checker watching contract and code.

ADR-0002 / 0008One default railthe unwalled rail is deleted (config error); model resolution has one precedence, an ST guards it behaviorally
ADR-0004A cap is a choiceunset = unlimited, set = stop with a receipt; no silent default numbers anywhere in the code
ADR-0006The factory audits itselfengine moved → exhibits turn red; the day is NOT closed without the “AWAITING YOU” list
Sandbox lifecycle — the two manual layers (memorize these two commands):
1 · cleanup after mergeThe sandbox must survive until the PR is merged (committer commits there). After the merge runs one command that removes the sandbox, prunes git state and deletes the merged branch safely: node scripts/flow.mjs --cleanup <name>
2 · work/ is invisible to testsTest collection excludes work/** — leftover sandboxes can never poison a full test run (the 24.11 lesson: 259 ghost files, 287 phantom red). Even an accumulation mistake stays invisible. vitest.config: exclude work/** · ST-26
